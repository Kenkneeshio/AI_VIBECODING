### Detailed crafted catalog and variant contract

The collection is deliberately original and data-driven. Its direction is detailed, realistic miniature construction—not flat stickers or toy-like distortion. Upholstery, wood, glass, ceramic, fabric, and metal should be recognizable through seams, piping, grain, joinery, hardware, panels, legs, bevels, highlights, and consistent contact shadows. Franchise names, copied characters, logos, recognizable branded silhouettes, and extracted game assets remain prohibited. The compatibility recipe names `cuteFurniture` and `cuteLight` remain stable internal identifiers only.

`inventory.js` owns searchable product metadata, stable IDs, authored footprints, and finish variants. `catalog-variants.js` derives deterministic Style, Size, and Finish choices. Style and Size replace `type` and apply authored `w`/`h`; Finish replaces `type` while preserving current `w`/`h`. Every change preserves stable item ID, center, rotation, bindings, and a customized name. `object-art.js` owns editor/export vectors and draws in actual item dimensions; `raster-renderer.js` keeps movable furniture/lights out of source crops; `render-contract.js` places furniture and ceiling devices.

The bed matrix is a standing regression contract: 42 entries, nine constructions (quilted, crib, toddler, platform, upholstered, storage, canopy, daybed, bunk), and six size classes (crib, toddler, twin, full, queen, king). Shared-family adult sizes grow monotonically, while equal-size constructions retain visibly and traceably different geometry. Tests cover four transforms, drawing richness, bounded operations, canvas-state balance, Android-safe APIs, deterministic choice ordering, finish-preserved geometry, and authored Style/Size geometry.

`object-controls.js`, `lib/dashboard-elements.ts`, and the local bridge project a validated `lightForm`; `roomcraft-card.js` supplies live state art. The whitelist remains `table_lamp`, `bud_lamp`, `cloud_floor_lamp`, `bloom_ceiling`, `star_pendant`, and `acorn_sconce`; missing or unknown values safely use `table_lamp`. Those values are transport compatibility IDs, not a mandate for decorative sticker shapes. A bound light appears once as a live overlay; only its own entity controls glow, unavailable treatment, and its 4-pixel state dot.

This art release does not change layout version 2, editable-reference migration version 4, room geometry, current item placement, or private device bindings. Its coordinated deployment intentionally regenerated only the plan PNG so the current furniture uses the new renderer; concurrency and full readback proved that the editable project and live elements were preserved.

1. Read this page, the [deterministic engine contract](engine-contract.md), [architecture](architecture.md), [layout contract](layout-format.md), and [deployment/rollback guide](deployment.md). 2. Work from `home-assistant/projects/roomcraft/site/`. Use Node.js 22.13 or newer and Python 3. Run `npm ci`, then the checks below. The public [synthetic layout](../examples/layout-v2.json) is safe for local development; the real dashboard JSON is private.
3. For live work, obtain authorized HA/Site access and the private management adapter from the owner. Do not infer credentials or installation coordinates from the public inventory. Take a private dashboard backup before any write.
4. Open `/second-floor/studio` through Home Assistant. It loads the current dashboard project on opening and preserves a different local draft for recovery. **Import from dashboard** refreshes an editor that is already open. If Chrome leaves the embedded editor blank, use **Open editor in a new tab** and keep Studio open; a direct `/local/roomcraft/editor.html` URL has no authenticated dashboard bridge.
   **← Dashboard** in the editor header returns to the plan. Unpublished edits prompt before navigation and stay in the browser draft; navigation does not export them. The owner-private Site gets the destination from its authenticated dashboard response.
5. Before changing a binding, confirm the physical device and current HA entity. The [sanitized inventory](ha-inventory/README.md) is a dated metadata snapshot, not a deployable config or live-state record.

Use this deterministic release sequence for every renderer/dashboard change. The [engine contract](engine-contract.md) defines the canonical inputs, layer and art rules, migration protocol, required evidence, ownership boundaries, and coordinated rollback behind these steps:

1. Run the checks above in both the canonical project and the Site checkout. The Android stability test must continue to reject executable canvas `shadowBlur` in all three renderers.
2. Commit and push the exact verified canonical source revision. Runtime deployments must be traceable to this immutable revision.
3. Push the exact tested Site source commit, package that same commit, save/deploy its version without changing the existing audience, and record the Site version and source SHA.
4. Save a private dashboard backup, then install the matching `public/` and `ha-local/` resources with `ha-local/install.py`; require complete file hashes plus dashboard/resource readback to pass.
5. Open Studio, import the saved dashboard project, export the intended 1536 × 864 image, and update only the plan image after a concurrency check. Read the dashboard back and assert `roomcraft_scene`, migration version, item count, and expected semantic furniture IDs before visual review.
6. Compare the authenticated uploaded PNG with a fresh 1920 × 1080 tablet capture. ## Runtime release and recovery

The [deployment guide](deployment.md) is the operational procedure. In order: review source and tests, save a private dashboard/image backup, publish the optional owner-private Site if its code changed, install/version HA assets and card using `python ha-local/install.py` with private host/key/adapter paths, export the intended layout from Studio, read back the HA dashboard, then check laptop and tablet. Keep the cloud and HA transports on compatible code. A GitHub merge alone changes neither installation.

The installer records a private backup. To roll back, restore that dashboard JSON through Home Assistant `lovelace/config/save`, read back the result, restore a known-good asset/card version if needed, and roll back the Site deployment separately if it changed. Preserve unsaved browser work as private JSON first. Do not place backups, tokens, SSH keys, raw entity inventories, camera media, or live dashboard exports in this repository or `/local/roomcraft/`.
